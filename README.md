# n4-ide

Десктопная IDE для фреймворка n4. Пишешь модель на Python прямо в редакторе, генерируешь датасет, запускаешь обучение и тут же смотришь, что получилось: вычислительный граф, схему слоёв, кривые метрик.

Задумывалось как способ увидеть автоград глазами, а не только по числам в консоли.

## Стек

- Python 3.13
- PyQt6, интерфейс целиком на нём
- QScintilla для редактора кода с подсветкой Python
- matplotlib для графиков метрик и отрисовки датасетов
- graphviz для рендера графов, дальше SVG показывается средствами Qt
- numpy
- n4, подтягивается из git
- uv как раннер, ruff и ty для проверок

## Как запускать

Зависимости зафиксированы в uv.lock, обновлять их не нужно, uv поднимет окружение сам.

```
uv run main.py
```

Что нужно кроме этого:

- графическая сессия, приложение открывает окно 1600 на 900
- системный graphviz, то есть бинарник dot в PATH. Python-пакет graphviz это только обёртка, сам он ничего не рисует

## Структура папок

Проект разложен на три слоя, и это правило соблюдается довольно жёстко.

- ide/presentation - только PyQt6 и ничего кроме. Главное окно собирает навбар слева и QStackedWidget с разделами: модель, датасет, визуализация, обучение, метрики. Рядом лежат переиспользуемые компоненты, свои кнопки, комбобоксы, панели, канва matplotlib
- ide/application - класс Application, центральное состояние и оркестрация. Менеджеры модели, датасета, обучения, файлов, состояния и общий обработчик ошибок. Наружу всё уходит сигналами Qt
- ide/domain - логика без единого импорта PyQt6. Выполнение пользовательского кода, датасеты, цикл обучения, сборщики метрик, построители графов, реестр числовых бекендов
- docs - гайд по n4 и схемы в drawio, диаграмма классов и схема алгоритмов
- examples - готовые модели, которые можно вставить в редактор: XOR и две спирали
- ui_export - макеты интерфейса, выгруженные в html. Это референс дизайна, в рантайме не используется
- assets/icons - иконки навбара и панелей

## Особенности

- Код модели пользователя разбирается через ast перед выполнением. Запрещены импорты os, sys, subprocess, socket, shutil и pathlib, плюс нельзя переопределять имена, занятые самим фреймворком. Это не настоящая песочница, скорее защита от случайного выстрела в ногу
- Обучение крутится в отдельном QThread, интерфейс во время него не подвисает, обучение можно остановить
- Слои общаются сигналами и передают неизменяемые dataclass-структуры. Presentation не ходит в domain напрямую
- Датасеты и метрики оформлены реестрами. Чтобы добавить новый датасет, достаточно описать класс с полями конфигурации, UI сам построит для них форму
- Числовой бекенд выбирается в интерфейсе, доступны PyFloat, NumpyFloat и DecimalNum, все три приезжают из n4
- Вычислительный граф на сколько-нибудь крупной модели получается очень большим. Экспорт в n4 специально урезан по деталям, но всё равно рендер может занять время
